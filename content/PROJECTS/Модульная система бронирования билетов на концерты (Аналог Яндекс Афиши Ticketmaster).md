###### Модульная система бронирования билетов на концерты (Аналог Яндекс Афиши Ticketmaster)

Вот обновленный, технически правильный бэклог. Теперь мы сначала собираем «живой» каркас системы (запускаем пустые сервисы, проверяем их связь с базой данных и Nginx) и только после этого переходим к согласованию и написанию логики данных.

---

## Спринт 1: Инфраструктурный каркас (Запуск «пустышек»)

## 🌐 Репозиторий `infrastructure`

- Таска 1.1: Настройка локального окружения, создание файла `.env` и проверка запуска пустой БД PostgreSQL.
- Таска 1.2: Создание базового конфигурационного файла для API Gateway (Nginx) с заглушками для роутинга.

## 🐍 Репозиторий `python-b2b`

- Таска 1.3: Инициализация пустого проекта (FastAPI/Django) с минимальным эндпоинтом-заглушкой (`GET /api/b2b/health`).
- Таска 1.4: Создание `Dockerfile` для Python-сервиса и проверка его успешной сборки через `docker-compose`.
- Таска 1.5: Настройка подключения к PostgreSQL и проверка связи («пинг» базы при старте приложения).

## ☕ Репозиторий `backend-java`

- Таска 1.6: Инициализация пустого проекта (Spring Boot) с минимальным эндпоинтом-заглушкой (`GET /api/v1/health`).
- Таска 1.7: Создание `Dockerfile` для Java-сервиса и проверка его успешной сборки через `docker-compose`.
- Таска 1.8: Настройка подключения к PostgreSQL и проверка связи (через конфигурацию DataSource).

## 🤝 Общекомандная задача (Проверка сквозного пути)

- Таска 1.9: Финальная проверка каркаса: запуск всей системы одной командой `docker-compose up`. Проверка, что Nginx успешно пробрасывает запросы снаружи до эндпоинтов-заглушек Java и Python.

---

## Спринт 2: Проектирование и подготовка БД

## 📝 Общекомандная задача (Архитектурный синк)

- Таска 2.1: Совместное проектирование схемы базы данных на бумаге / в диаграмме (таблицы Мероприятий, Залов, Сеансов, Билетов). Согласование типов данных и правил именования полей (например, `snake_case`).

## 🐍 Репозиторий `python-b2b` (как главный по наполнению БД)

- Таска 2.2: Настройка инструмента миграций (Alembic) в Python-репозитории.
- Таска 2.3: Написание первой миграции для создания согласованной структуры таблиц в PostgreSQL.
- Таска 2.4: Создание ORM-моделей в Python-коде на основе созданных таблиц.

## ☕ Репозиторий `backend-java`

- Таска 2.5: Создание сущностей (Entities) и репозиториев (Repositories) в Java-коде, которые будут читать и обновлять данные в уже созданных Python-миграцией таблицах.

---

## Спринт 3: Реализация B2B и B2C бизнес-логики

## 🐍 Репозиторий `python-b2b` (Панель Организатора)

- Таска 3.1: Разработка API для управления площадками (кинотеатры, театры) и конфигурацией схем залов.
- Таска 3.2: Разработка API для создания карточек мероприятий (описание, постеры).
- Таска 3.3: Разработка API для создания сеансов в расписании и автоматической генерации мест под них.
- Таска 3.4: Разработка API для получения B2B-отчетов по продажам для партнеров.

## ☕ Репозиторий `backend-java` (Витрина и Покупка)

- Таска 3.5: Разработка API каталога (выдача списка всех мероприятий с фильтрацией по датам/типам и пагинацией).
- Таска 3.6: Разработка API детальной страницы конкретного мероприятия (описание и список доступных сеансов/мест).
- Таска 3.7: Разработка транзакционной логики бронирования и покупки билета (защита от одновременной покупки одного места двумя пользователями).
- Таска 3.8: Разработка API валидации купленных билетов (для контроля на входе в зал).

---

## Спринт 4: Безопасность и Авторизация

- Таска 4.1 (Python): Регистрация и JWT-авторизация для Бизнес-партнеров (Организаторов).
- Таска 4.2 (Java): Регистрация, JWT-авторизация и Личный кабинет с историей заказов для обычных Пользователей.

Такой план выглядит гораздо безопаснее для старта разработки с нуля. С чего начнем?

- Нам нужно детализировать задачи Спринта 1 (написать конкретные конфиги для `Dockerfile` и `nginx.conf` под ваш compose)?
- Или хотите сначала вместе набросать схему таблиц базы данных (Спринт 2), чтобы вы визуально понимали, как сервисы будут связаны через Postgres?
